# i-Telex peripheral firmware (TxP2)

> **This repository is a clone of Fred Sonnenrein's excellent i-Telex
> sources.** Fred is the author and long-time maintainer of this work; the
> project history preserved here comes from his original SourceForge SVN
> repository. This GitHub repository is intended to preserve that work and make
> it easier to read and reference. It should not be mistaken for a separately
> authored project.

Where the [`itelex`](https://github.com/toresbe/itelex) repository holds the
firmware for the i-Telex module itself — the card that carries teleprinter
traffic over IP — this repository holds the firmware for the remaining cards of
an i-Telex system and the sources they share: the TW39, ED1000, V.21 and
analogue modem line interfaces, the Hellschreiber and Tloch15 units, the
measuring and universal interfaces, and the `Gemeinsam/` sources (Baudot code
tables, backplane bus communication, FIFO buffers, configuration storage) that
the i-Telex module firmware also builds against as a submodule.

The Doxygen configuration and GitHub Actions workflow added in this clone are
maintenance around Fred's sources. They do not change their provenance.

## Documentation

The Doxygen documentation for `main` is published at
**[toresbe.github.io/itelex-misc](https://toresbe.github.io/itelex-misc/)** and
is regenerated by CI on every push to `main`.

The documentation is rendered in German, matching the sources and the
`PROJECT_NAME` of `TxP2` in the inherited `Doxyfile`.

## Building the documentation locally

On Debian 13 or similar:

```sh
sudo apt install doxygen graphviz
mkdir -p build/docs
doxygen Doxyfile.github
```

The rendered site is then in `build/docs/`; open `build/docs/index.html`.

`Doxyfile` is the historical configuration as it came from the SVN repository,
written for a Windows workstation: it writes into `Doxygen/`, splits the HTML
into an `html/` subdirectory, and expects no Graphviz installation.
`Doxyfile.github` includes it and overrides only what publishing needs — the
output location, a self-contained HTML tree, Graphviz from `PATH` for the
include and caller graphs, and the client-side search index. Editing settings
that both files share belongs in `Doxyfile`.

## Firmware builds

The per-card firmware is still built with the inherited AVR Studio projects and
`make.bat`/`makeall.bat` batch files, driven from `makeall.bat` in the
repository root. Those builds are unchanged and are not run by CI; only the
documentation is.

## Repository layout

- `Gemeinsam/` holds the sources shared between the cards, and is what the
  `itelex` firmware consumes as a submodule.
- `AnalogModem2/`, `ED1000/`, `FernschrOhneFSG/`, `FernschrTW39/`,
  `FernschrTW39plus/`, `FernschrV21_aufLA2/`, `Hellschreiber/`, `Messgeraet/`,
  `SeriellUndSpeicher/`, `SignalZusatz/`, `Tloch15/`, `UniversalIF/` and
  `Wahlbruecke/` are the per-card firmware projects.
- `SeriellPurAlsBeispiel/` is a minimal serial example.
- `AlleBins/` is where `MakeBins.bat` gathers the flashable `.bin` images and
  their fuse settings for distribution; only its generated index is tracked.
  `FuseMuster/` holds the fuse patterns themselves and `Hardware/` the board
  documentation.
- `KommLogs/` holds protocol captures, and the remaining root-level Office
  documents are the author's project notes on the TxP2 protocol and code.

## Continuous integration

GitHub Actions renders the Doxygen HTML in a Debian 13 container on pushes and
pull requests and uploads it as the `itelex-misc-documentation` workflow
artifact. Pushes to `main` additionally deploy it to GitHub Pages at the address
given under [Documentation](#documentation) above.
